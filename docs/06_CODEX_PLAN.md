# Codex 구현 단계와 수용 기준

## 단계 0: 근거·콘텐츠 감사
- 데이터 유효성 검사, 각 claim/문항/전통의 참조 무결성 테스트
- 전문가 검토용 문항 에디터, `review_status` 컬럼, 문장 편향 점검
- 기준 문헌 URL·문단번호 검증 및 원전/해석 차이 구분
- 타입 정의를 만든 뒤 검사 엔진을 순수 함수로 구현

## 단계 1: 웹 앱
- Next.js App Router/TypeScript/Tailwind 또는 Vite+React+TS 중 하나 선택. 의존성 간소화 우선.
- 섹션 네비게이션, 동의 척도, 모름, 복수 선택 후속질문, 답변 자동 저장/가져오기
- 오류·완료 상태 및 접근성 처리
- 블라인드: 문항 페이지 번들/HTML/DOM에서 분류 정답/신학자명을 뽑아낼 수 없도록 필요 데이터만 전달

## 단계 2: 분석/결과
- 주장별 지지도, 자료충분성, 명시적 유보, 상반되는 진술 간 내적 긴장
- 도메인별 지형, 출처가 연결된 신조 대조
- 사료에 기반한 전통의 친연성(공통 분모, coverage 포함)
- 학자별 비교는 출처 확인 전까진 비활성화
- 결과 예시: '성화: 전적 성결 긍정, 은사의 지속: 가능성 긍정, 방언의 필수 증거: 반대 → 웨슬리안 성결과 은사지속론 성향의 교차 프로필'

## 단계 3: 검증
- 신학 검수: 공교회신조 연구자 + 개혁파·웨슬리안·루터교·가톨릭·정교회 등 다른 전통의 전문가 각 1인 이상 권장
- 측정학 검수: 문항 의미·선택지 대칭·동일 문항 반복 여부·자료충분성·결측 처리
- 사용자 테스트: 모바일/PC, 화면 모드, 키보드, 스크린리더, 저장/복구, 다중 브라우저
- 사용자 동의 있는 파일럿 결과로 경계값을 조정. **일치율·정확도 등 검증 전 수치 마케팅 금지**

## 자동 수용 테스트 (필수)
- 정확히 120개 기초 문항 (36×3+12)
- 문항 ID 전부 고유, 토픽 ID·사료 ID 모두 존재
- 블라인드 화면에서 `stance_label`, `tradition_name`, `heretic` 등 민감 메타 데이터 미노출
- unknown/null은 결측 처리, Likert 3과 구분
- 형벌대속과 그리스도 승리를 동시에 지지할 수 있음
- 신조 유보/모름은 이단 위험으로 표시되지 않음
- 전통 비교가 1~2개 문항으로 확정되는 것 방지
- 모든 Q heading + option의 computed color는 실제로 대비비 >=4.5:1
- 375px 모바일에서 가로 스크롤/잘림/다음 버튼 비활성 문제 없음
- 중단 재개·입력 변경·JSON 저장/복구·데이터 버전 마이그레이션
